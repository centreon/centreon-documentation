## Dépendances du connecteur de supervision

Les connecteurs de supervision suivants sont automatiquement installés lors de l'installation du connecteur **Redis Labs Enterprise Cluster Rest API**
depuis la page **Configuration > Connecteurs > Connecteurs de supervision** :
* [Base Pack](./base-generic.md)

## Contenu du pack

### Modèles

Le connecteur de supervision **Redis Labs Enterprise Cluster Rest API** apporte un modèle d'hôte :

* **App-Redis-Rlec-Restapi-custom**

Le connecteur apporte les modèles de service suivants
(classés selon le modèle d'hôte auquel ils sont rattachés) :

<Tabs groupId="sync">
<TabItem value="App-Redis-Rlec-Restapi-custom" label="App-Redis-Rlec-Restapi-custom">

| Alias     | Modèle de service                       | Description                                    |
|:----------|:----------------------------------------|:-----------------------------------------------|
| Cluster   | App-Redis-Rlec-Restapi-Cluster-custom   | Contrôle les statistiques du cluster           |
| Databases | App-Redis-Rlec-Restapi-Databases-custom | Contrôle les statistiques des bases de données |
| Nodes     | App-Redis-Rlec-Restapi-Nodes-custom     | Contrôle les statistiques des noeuds           |
| Shards    | App-Redis-Rlec-Restapi-Shards-custom    | Contrôle les statistiques des shards           |

> Les services listés ci-dessus sont créés automatiquement lorsque le modèle d'hôte **App-Redis-Rlec-Restapi-custom** est utilisé.

</TabItem>
</Tabs>

## Prérequis

Afin d’utiliser ce connecteur, il faut un compte disposant de droits de lecture sur l’API REST du cluster Redis Labs Enterprise. Pour plus d’informations, référez-vous à la [documentation officielle](https://redis.io/docs/latest/operate/rs/references/rest-api/).

## Installer le connecteur de supervision

### Pack

La procédure d'installation des connecteurs de supervision diffère légèrement [suivant que votre licence est offline ou online](../getting-started/how-to-guides/connectors-licenses.md).

1. Si la plateforme est configurée avec une licence *online*, l'installation d'un paquet
n'est pas requise pour voir apparaître le connecteur dans le menu **Configuration > Connecteurs > Connecteurs de supervision**.
Au contraire, si la plateforme utilise une licence *offline*, installez le paquet
sur le **serveur central** via la commande correspondant au gestionnaire de paquets
associé à sa distribution :

<Tabs groupId="sync">
<TabItem value="Alma / RHEL / Oracle Linux 8" label="Alma / RHEL / Oracle Linux 8">

```bash
dnf install centreon-pack-applications-redis-rlec-restapi
```

</TabItem>
<TabItem value="Alma / RHEL / Oracle Linux 9" label="Alma / RHEL / Oracle Linux 9">

```bash
dnf install centreon-pack-applications-redis-rlec-restapi
```

</TabItem>
<TabItem value="Debian 11 & 12" label="Debian 11 & 12">

```bash
apt install centreon-pack-applications-redis-rlec-restapi
```

</TabItem>
<TabItem value="CentOS 7" label="CentOS 7">

```bash
yum install centreon-pack-applications-redis-rlec-restapi
```

</TabItem>
</Tabs>

2. Quel que soit le type de la licence (*online* ou *offline*), installez le connecteur **Redis Labs Enterprise Cluster Rest API**
depuis l'interface web et le menu **Configuration > Connecteurs > Connecteurs de supervision**.

## Utiliser le connecteur de supervision

### Utiliser un modèle d'hôte issu du connecteur

1. Ajoutez un hôte à Centreon depuis la page **Configuration > Hôtes**.
2. Complétez les champs **Nom**, **Alias** & **IP Address/DNS** correspondant à votre ressource.
3. Appliquez le modèle d'hôte **App-Redis-Rlec-Restapi-custom**. Une liste de macros apparaît. Les macros vous permettent de définir comment le connecteur se connectera à la ressource, ainsi que de personnaliser le comportement du connecteur.
4. Renseignez les macros désirées. Attention, certaines macros sont obligatoires.

| Macro                    | Description                                                                                          | Valeur par défaut | Obligatoire |
|:-------------------------|:-----------------------------------------------------------------------------------------------------|:------------------|:-----------:|
| REDISRLECAPIUSERNAME     | Cluster username                                                                                     |                   | X            |
| REDISRLECAPIPASSWORD     | Cluster password                                                                                     |                   | X            |
| REDISRLECAPIPROTO        | Specify https if needed (default: 'https')                                                           | https             | X            |
| REDISRLECAPIPORT         | Port used (default: 9443)                                                                            | 9443              | X            |
| REDISRLECAPIEXTRAOPTIONS | Any extra option you may want to add to every command (a --verbose flag for example). Toutes les options sont listées [ici](#options-disponibles). |                   |             |

5. [Déployez la configuration](/docs/monitoring/monitoring-servers/deploying-a-configuration). L'hôte apparaît dans la liste des hôtes supervisés, et dans la page **Statut des ressources**. La commande envoyée par le connecteur est indiquée dans le panneau de détails de l'hôte : celle-ci montre les valeurs des macros.

### Utiliser un modèle de service issu du connecteur

1. Si vous avez utilisé un modèle d'hôte et coché la case **Créer aussi les services liés aux modèles**, les services associés au modèle ont été créés automatiquement, avec les modèles de services correspondants. Sinon, [créez les services désirés manuellement](/docs/monitoring/basic-objects/services) et appliquez-leur un modèle de service.
2. Renseignez les macros désirées (par exemple, ajustez les seuils d'alerte). Les macros indiquées ci-dessous comme requises (**Obligatoire**) doivent être renseignées.

### Modes disponibles

Dans la plupart des cas, un mode correspond à un modèle de service. Le mode est renseigné dans la commande d'exécution
du connecteur. Dans l'interface de Centreon, il n'est pas nécessaire de les spécifier explicitement, leur utilisation est
implicite dès lors que vous utilisez un modèle de service. En revanche, vous devrez spécifier le mode correspondant à ce
modèle si vous voulez tester la commande d'exécution du connecteur dans votre terminal.

/usr/lib/centreon/plugins/centreon_redis_rlec_restapi.pl \
	--plugin=apps::redis::rlec::restapi::plugin \
