## Prérequis

Le connecteur interroge l'API JSON publique d'une page de statut hébergée sur
Atlassian Statuspage. Aucun compte ni clé d'API n'est nécessaire.

* Le collecteur doit pouvoir joindre la page de statut sur le port TCP/443,
  directement ou via un proxy (option `--proxyurl`).
* Dans Centreon, le champ **IP Address/DNS** de l'hôte contient le nom de
  domaine de la page de statut, par exemple `www.githubstatus.com`.

Pour vérifier qu'une page de statut est compatible, ouvrez
`https://<nom de domaine de la page de statut>/api/v2/components.json` dans un
navigateur : l'adresse doit renvoyer la liste de ses composants au format
JSON. De nombreuses pages de statut publiques utilisent Atlassian Statuspage,
par exemple celles de GitHub, Discord, Reddit, Datadog, Jira et Confluence.

## Utiliser le connecteur de supervision

### Utiliser un modèle d'hôte issu du connecteur

1. Ajoutez un hôte à Centreon depuis la page **Configuration > Hôtes**.
2. Complétez les champs **Nom**, **Alias** & **IP Address/DNS** correspondant à votre ressource.
3. Appliquez le modèle d'hôte **App-Atlassian-Statuspage-Api-custom**. Une liste de macros apparaît. Les macros vous permettent de définir comment le connecteur se connectera à la ressource, ainsi que de personnaliser le comportement du connecteur.
4. Renseignez les macros désirées. Attention, certaines macros sont obligatoires.

| Macro                    | Description                                                                                                                                        | Valeur par défaut | Obligatoire |
|:-------------------------|:---------------------------------------------------------------------------------------------------------------------------------------------------|:------------------|:-----------:|
| STATUSPAGE_PROTO         | Specify https if needed (default: 'https')                                                                                                         | https             |             |
| STATUSPAGE_PORT          | Port used (default: 443)                                                                                                                           | 443               |             |
| STATUSPAGE_API_PATH      | API base URL path (default: '/api/v2/')                                                                                                            | /api/v2/          |             |
| STATUSPAGE_EXTRA_OPTIONS | Any extra option you may want to add to every command (a --verbose flag for example). Toutes les options sont listées [ici](#options-disponibles). |                   |             |

5. [Déployez la configuration](/docs/monitoring/monitoring-servers/deploying-a-configuration). L'hôte apparaît dans la liste des hôtes supervisés, et dans la page **Statut des ressources**. La commande envoyée par le connecteur est indiquée dans le panneau de détails de l'hôte : celle-ci montre les valeurs des macros.

## Comment puis-je tester le plugin et que signifient les options des commandes ?

Une fois le plugin installé, vous pouvez tester celui-ci directement en ligne
de commande depuis votre collecteur Centreon en vous connectant avec
l'utilisateur **centreon-engine** (`su - centreon-engine`). Vous pouvez tester
que le connecteur arrive bien à superviser une ressource en utilisant une commande
telle que celle-ci (remplacez les valeurs d'exemple par les vôtres) :

```bash
/usr/lib/centreon/plugins/centreon_atlassian_statuspage_api.pl \
	--plugin=apps::atlassian::statuspage::api::plugin \
	--custommode=json \
	--mode=components \
	--hostname='www.githubstatus.com' \
	--port='443' \
	--proto='https' \
	--api-path='/api/v2/' \
	--include-id='' \
	--exclude-id='' \
	--include-name='' \
	--exclude-name='' \
	--include-group='' \
	--exclude-group='' \
	--unknown-status='%{status} =~ /unknown/' \
	--warning-status='%{status} =~ /degraded performance|partial outage/' \
	--critical-status='%{status} =~ /major outage/' \
	--verbose
```

La commande devrait retourner un message de sortie similaire à :

```bash
OK: All components are ok
Component 'Actions' [group: github.com] status: operational
Component 'Copilot AI Model Providers' [group: ads.github.com] status: operational
Component 'Issues' [group: github.com] status: operational
Component 'API Requests' [group: github.com] status: operational
Component 'Codespaces' [group: github.com] status: operational
Component 'Pages' [group: github.com] status: operational
Component 'Copilot' status: operational
Component 'Packages' [group: github.com] status: operational
Component 'Git Operations' [group: github.com] status: operational
Component 'Pull Requests' status: operational
Component 'Webhooks' [group: github.com] status: operational
```

### Modes disponibles

Dans la plupart des cas, un mode correspond à un modèle de service. Le mode est renseigné dans la commande d'exécution 
du connecteur. Dans l'interface de Centreon, il n'est pas nécessaire de les spécifier explicitement, leur utilisation est
implicite dès lors que vous utilisez un modèle de service. En revanche, vous devrez spécifier le mode correspondant à ce
modèle si vous voulez tester la commande d'exécution du connecteur dans votre terminal.

Tous les modes disponibles peuvent être affichés en ajoutant le paramètre
`--list-mode` à la commande :

```bash
/usr/lib/centreon/plugins/centreon_atlassian_statuspage_api.pl \
	--plugin=apps::atlassian::statuspage::api::plugin \
	--custommode=json \
	--list-mode
```
