## Dépendances du connecteur de supervision

Les connecteurs de supervision suivants sont automatiquement installés lors de l'installation du connecteur **Vates Pool REST API** 
depuis la page **Configuration > Connecteurs > Connecteurs de supervision** :
* [Base Pack](./base-generic.md)

## Contenu du pack

### Modèles

Le connecteur de supervision **Vates Pool REST API** apporte un modèle d'hôte :

* **Virt-Vates-Pool-Restapi-custom**

Le connecteur apporte le modèle de service suivant
(classé selon le modèle d'hôte auquel il est rattaché) :

<Tabs groupId="sync">
<TabItem value="Virt-Vates-Pool-Restapi-custom" label="Virt-Vates-Pool-Restapi-custom">

| Alias          | Modèle de service                             | Description                                                                                                                                                                           |
|:---------------|:----------------------------------------------|:--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| Cpu-Overcommit | Virt-Vates-Pool-CPU-Overcommit-Restapi-custom | supervise le ratio nombre de CPU affecté à toutes les machines virtuelle contre le nombre de CPU présent dans le pool. Cette valeur est un pourcentage qui peux être supérieur à 100. |

> Les services listés ci-dessus sont créés automatiquement lorsque le modèle d'hôte **Virt-Vates-Pool-Restapi-custom** est utilisé.

</TabItem>
</Tabs>

## Prérequis

Pour créer un utilisateur ayant seulement les droits de lecture, vous pouvez utiliser l'option `--create-xoa-read-only-user` du plugin, par exemple : 

```bash
/usr/lib/centreon/plugins/centreon_vates_xen_orchestra_restapi.pl --plugin='apps::virtualization::vates::pool::plugin' --mode='discovery' --password='YourAdminPasswordHere' --username='admin' --hostname='XoaAddressOrIp.com' --create-xoa-read-only-user
```

Vous pouvez utiliser `--insecure` si vous n'avez pas de certificats reconnus, et `--debug` pour observer les appels api exacts effectués.

Si la création automatisée ne fonctionne pas, vous pouvez créer un utilisateur via l'interface web à la place.

## Utiliser le connecteur de supervision

### Utiliser un modèle d'hôte issu du connecteur

1. Ajoutez un hôte à Centreon depuis la page **Configuration > Hôtes**.
2. Complétez les champs **Nom**, **Alias** & **IP Address/DNS** correspondant à votre ressource.
3. Appliquez le modèle d'hôte **Virt-Vates-Pool-Restapi-custom**. Une liste de macros apparaît. Les macros vous permettent de définir comment le connecteur se connectera à la ressource, ainsi que de personnaliser le comportement du connecteur.
4. Renseignez les macros désirées. Attention, certaines macros sont obligatoires.

| Macro         | Description                                                                                                                                        | Valeur par défaut | Obligatoire |
|:--------------|:---------------------------------------------------------------------------------------------------------------------------------------------------|:------------------|:-----------:|
| VATESHOSTNAME | Define the hostname of the Vates server                                                                                                            |                   |      X      |
| VATESUSERNAME | Define the username for authentication                                                                                                             |                   |      X      |
| VATESPASSWORD | Define the password for authentication                                                                                                             |                   |      X      |
| VATESPROTO    | Define the protocol to use                                                                                                                         | https             |             |
| VATESPORT     | Define the port of the Vates server                                                                                                                | 443               |             |
| VATESPOOLUUID | Identify the pool by its exact uuid                                                                                                                |                   |             |
| EXTRAOPTIONS  | Any extra option you may want to add to every command (a --verbose flag for example). Toutes les options sont listées [ici](#options-disponibles). |                   |             |

5. [Déployez la configuration](/docs/monitoring/monitoring-servers/deploying-a-configuration). L'hôte apparaît dans la liste des hôtes supervisés, et dans la page **Statut des ressources**. La commande envoyée par le connecteur est indiquée dans le panneau de détails de l'hôte : celle-ci montre les valeurs des macros.

### Utiliser un modèle de service issu du connecteur

1. Si vous avez utilisé un modèle d'hôte et coché la case **Créer aussi les services liés aux modèles**, les services associés au modèle ont été créés automatiquement, avec les modèles de services correspondants. Sinon, [créez les services désirés manuellement](/docs/monitoring/basic-objects/services) et appliquez-leur un modèle de service.
2. Renseignez les macros désirées (par exemple, ajustez les seuils d'alerte). Les macros indiquées ci-dessous comme requises (**Obligatoire**) doivent être renseignées.

<Tabs groupId="sync">

|:-----------------------------|:-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|:------------------|:-----------:|
| WARNING_CPU_OVERCOMMIT_PRCT  | Threshold warning for the CPU over commit ratio, in percentage. Note that this metric can go over 100%. 100% mean the sum of CPU assigned to virtual machines is equal to the physical number of CPU in the pool Default: 90   | 90                |             |
| CRITICAL_CPU_OVERCOMMIT_PRCT | Threshold critical for the CPU over commit ratio, in percentage. Note that this metric can go over 100%. 100% mean the sum of CPU assigned to virtual machines is equal to the physical number of CPU in the pool Default: 100 | 100               |             |
| EXTRAOPTIONS                 | Any extra option you may want to add to the command (a --verbose flag for example). Toutes les options sont listées [ici](#options-disponibles).                                                                               |                   |             |

3. [Déployez la configuration](/docs/monitoring/monitoring-servers/deploying-a-configuration). Le service apparaît dans la liste des services supervisés, et dans la page **Statut des ressources**. La commande envoyée par le connecteur est indiquée dans le panneau de détails du service : celle-ci montre les valeurs des macros.

## Comment puis-je tester le plugin et que signifient les options des commandes ?

Une fois le plugin installé, vous pouvez tester celui-ci directement en ligne
de commande depuis votre collecteur Centreon en vous connectant avec
l'utilisateur **centreon-engine** (`su - centreon-engine`). Vous pouvez tester
que le connecteur arrive bien à superviser une ressource en utilisant une commande
telle que celle-ci (remplacez les valeurs d'exemple par les vôtres) :

```bash
/usr/lib/centreon/plugins/centreon_vates_pool_restapi.pl \
	--plugin=apps::virtualization::vates::pool::plugin \
	--custommode=api \
	--mode=cpu-over-commit \
	--hostname='' \
	--port='443' \
	--proto='https' \
	--username='username' \
	--password='password'  \
	--pool-uuid='' \
	--pool-name='' \
	--warning-cpu-overcommit-prct='90' \
	--critical-cpu-overcommit-prct='100' 
```

La commande devrait retourner un message de sortie similaire à :

```bash
OK: CPU overcommit ratio is 27566 % | 'pool.cpu.overcommit.percentage'=27566%;90;100;0; 
```

### Diagnostic des erreurs communes

Rendez-vous sur la [documentation dédiée](../getting-started/how-to-guides/troubleshooting-plugins.md#contrôles-http-et-api)

### Modes disponibles

Dans la plupart des cas, un mode correspond à un modèle de service. Le mode est renseigné dans la commande d'exécution 
du connecteur. Dans l'interface de Centreon, il n'est pas nécessaire de les spécifier explicitement, leur utilisation est
implicite dès lors que vous utilisez un modèle de service. En revanche, vous devrez spécifier le mode correspondant à ce
modèle si vous voulez tester la commande d'exécution du connecteur dans votre terminal.

Tous les modes disponibles peuvent être affichés en ajoutant le paramètre
`--list-mode` à la commande :

```bash
/usr/lib/centreon/plugins/centreon_vates_pool_restapi.pl \
	--plugin=apps::virtualization::vates::pool::plugin \
	--list-mode
```

Le plugin apporte les modes suivants :

| discovery [[code](https://github.com/centreon/centreon-plugins/blob/develop/src/apps/virtualization/vates/pool/mode/discovery.pm)]           | Utilisé pour la découverte d'hôtes            |
