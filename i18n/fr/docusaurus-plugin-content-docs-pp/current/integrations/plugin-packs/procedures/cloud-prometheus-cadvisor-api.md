## Dépendances du connecteur de supervision

Les connecteurs de supervision suivants sont automatiquement installés lors de l'installation du connecteur **cAdvisor w/ Prometheus API** 
depuis la page **Configuration > Connecteurs > Connecteurs de supervision** :

## Contenu du pack

### Modèles

Le connecteur de supervision **cAdvisor w/ Prometheus API** apporte 4 modèles d'hôte :

* **Cloud-Prometheus-cAdvisor-Api-custom** : supervise depuis un seul hôte tous les conteneurs correspondant aux filtres de chaque service.
* **Cloud-Prometheus-cAdvisor-Api-Container-custom** : supervise un conteneur exécuté hors de Kubernetes (Docker, Podman).
* **Cloud-Prometheus-cAdvisor-Api-Kubernetes-Container-custom** : supervise un conteneur d'un pod Kubernetes.
* **Cloud-Prometheus-cAdvisor-Api-Pod-custom** : supervise un pod Kubernetes dans son ensemble.

Les trois derniers modèles d'hôte contrôlent que leur pod ou leur conteneur est présent dans les métriques. Ils sont conçus pour être appliqués par la [découverte d'hôtes](#découverte-dhôtes).

### Règles de découverte

#### Découverte d'hôtes

| Nom de la règle     | Description                                                                                                            |
|:--------------------|:-----------------------------------------------------------------------------------------------------------------------|
| Prometheus cAdvisor | Découvre les pods et les conteneurs (Kubernetes ou autonomes) à partir des métriques cAdvisor stockées dans Prometheus |

La découverte liste les pods et les conteneurs à partir de la métrique `container_last_seen`, puis applique un modèle d'hôte selon le type de chaque ressource découverte :

| Ressource découverte                 | Modèle d'hôte                                             | Nom de l'hôte             |
|:-------------------------------------|:----------------------------------------------------------|:--------------------------|
| Pod Kubernetes                       | Cloud-Prometheus-cAdvisor-Api-Pod-custom                  | `namespace_pod`           |
| Conteneur d'un pod Kubernetes        | Cloud-Prometheus-cAdvisor-Api-Kubernetes-Container-custom | `namespace_pod_container` |
| Conteneur exécuté hors de Kubernetes | Cloud-Prometheus-cAdvisor-Api-Container-custom            | `container`               |

La découverte renseigne aussi les macros des hôtes : la connexion à Prometheus, ainsi que les filtres **CONTAINER_FILTER**, **POD_FILTER** et **NAMESPACE_FILTER**, qui sélectionnent le pod ou le conteneur de chaque hôte.

Rendez-vous sur la [documentation dédiée](/docs/monitoring/discovery/hosts-discovery) pour en savoir plus sur la découverte d'hôtes, notamment sur la façon de planifier l'exécution de la tâche de découverte pour ajouter les hôtes des nouveaux pods au fil de l'évolution de votre cluster Kubernetes.

## Prérequis

### Prometheus et cAdvisor

Le connecteur interroge l'API d'un serveur Prometheus qui collecte les métriques cAdvisor, depuis l'une des sources suivantes :

* **Le cAdvisor intégré au kubelet** (Kubernetes) : le point d'accès `/metrics/cadvisor` de chaque nœud, généralement collecté par le job `kubelet` du Prometheus Operator. Il exporte les métriques CPU et mémoire des pods et des conteneurs. Il n'exporte pas les métriques de charge (`container_cpu_load_average_10s`) et d'état des tâches (`container_tasks_state`), ni l'occupation disque des conteneurs `containerd`.
* **Un cAdvisor autonome** : sur un hôte Docker ou Podman, ou déployé dans Kubernetes sous forme de DaemonSet. Il est nécessaire pour utiliser les services de charge, de stockage et d'état des tâches.

Les filtres par défaut utilisent les labels `container`, `pod` et `namespace` définis par le kubelet depuis Kubernetes 1.16 (OpenShift 4.3). Sur les plateformes plus anciennes, ces labels s'appellent `container_name` et `pod_name` : adaptez les filtres en conséquence, par exemple `--container='container_name!~"|.*POD.*"' --pod='pod_name=~".*"'`.

Un cAdvisor autonome déployé dans Kubernetes ne définit pas ces labels. Il expose uniquement les labels du moteur de conteneurs (par exemple `container_label_io_kubernetes_pod_name`). Dans ce cas, vous pouvez soit :

- Adapter les filtres à ces noms de labels.
- Configurer Prometheus pour copier ces labels vers container, pod et namespace (par exemple avec metric_relabel_configs).

### Bonne pratique : nommer vos conteneurs

cAdvisor identifie chaque conteneur par son nom.
Par défaut, Docker attribue un nouveau nom aléatoire à chaque recréation de conteneur.
Centreon crée alors de nouvelles métriques et un nouveau fichier RRD dans /var/lib/centreon/metrics, accumulant des données obsolètes.

**Attribuez toujours un nom fixe à chaque conteneur supervisé :**

```bash
# Ligne de commande
docker run -d --name mon-nginx nginx

# Docker Compose
services:
  web:
    image: nginx
    container_name: mon-nginx
```

> Si vous utilisez Kubernetes, les pods d'un `StatefulSet` gardent un nom stable (`mon-service-0`, `mon-service-1`, etc.), tout comme les pods créés directement (`kind: Pod`).
> Les pods des autres contrôleurs (`Deployment`, `DaemonSet`, `Job`, `CronJob`, etc.) reçoivent un nouveau nom à chaque recréation : la découverte d'hôtes peut être configurée pour ajouter un nouvel hôte à chaque changement de nom, et supprimer l'ancien, mais les métriques collectées pour deux noms différents ne seront ni liées ni visibles ensemble.

## Installer le connecteur de supervision

### Pack

La procédure d'installation des connecteurs de supervision diffère légèrement [suivant que votre licence est offline ou online](../getting-started/how-to-guides/connectors-licenses.md).

n'est pas requise pour voir apparaître le connecteur dans le menu **Configuration > Connecteurs > Connecteurs de supervision**.

sur le **serveur central** via la commande correspondant au gestionnaire de paquets
associé à sa distribution :

## Comment puis-je tester le plugin et que signifient les options des commandes ?

Une fois le plugin installé, vous pouvez tester celui-ci directement en ligne
de commande depuis votre collecteur Centreon en vous connectant avec
l'utilisateur **centreon-engine** (`su - centreon-engine`). Vous pouvez tester
que le connecteur arrive bien à superviser une ressource en utilisant une commande
telle que celle-ci (remplacez les valeurs d'exemple par les vôtres) :

```bash
/usr/lib/centreon/plugins/centreon_prometheus_cadvisor_api.pl \
	--plugin=cloud::prometheus::exporters::cadvisor::plugin \
	--mode=memory \
	--hostname=10.0.0.1 \
	--url-path='/api/v1' \
	--port='9090' \
	--proto='http' \
	--container='container="nginx"' \
	--pod='pod="web-1"' \
	--extra-filter='namespace="default"' \
	--warning-usage='' \
	--critical-usage='' \
	--warning-working='' \
	--critical-working='' \
	--warning-cache='' \
	--critical-cache='' \
	--warning-rss='' \
	--critical-rss='' \
	--warning-swap='' \
	--critical-swap='' \
	--verbose
```

La commande devrait retourner un message de sortie similaire à :

```bash
OK: Container 'nginx' [pod: web-1] Memory Usage: 50.00 MB (50.00% of 100.00 MB), Working: 40.00 MB (40.00% of 100.00 MB), Cache: 10.00 MB, Rss: 38.00 MB, Swap: 0.00 B | 'web-1~nginx#memory.used.bytes'=52428800B;;;0;104857600 'web-1~nginx#memory.working.bytes'=41943040B;;;0;104857600 'web-1~nginx#cache.usage.bytes'=10485760B;;;0; 'web-1~nginx#rss.usage.bytes'=39845888B;;;0; 'web-1~nginx#swap.usage.bytes'=0B;;;0;
Container 'nginx' [pod: web-1] Memory Usage: 50.00 MB (50.00% of 100.00 MB), Working: 40.00 MB (40.00% of 100.00 MB), Cache: 10.00 MB, Rss: 38.00 MB, Swap: 0.00 B
```

### Modes disponibles

Dans la plupart des cas, un mode correspond à un modèle de service. Le mode est renseigné dans la commande d'exécution 
du connecteur. Dans l'interface de Centreon, il n'est pas nécessaire de les spécifier explicitement, leur utilisation est
implicite dès lors que vous utilisez un modèle de service. En revanche, vous devrez spécifier le mode correspondant à ce
modèle si vous voulez tester la commande d'exécution du connecteur dans votre terminal.

Tous les modes disponibles peuvent être affichés en ajoutant le paramètre
`--list-mode` à la commande :

```bash
/usr/lib/centreon/plugins/centreon_prometheus_cadvisor_api.pl \
	--plugin=cloud::prometheus::exporters::cadvisor::plugin \
	--list-mode

OpenShift: `container_name` and `pod_name` only up to 4.1 (Kubernetes 1.13), both label sets in 4.2 (Kubernetes 1.14), `container` and `pod` only from 4.3 (Kubernetes 1.16). Rancher: depends on the Kubernetes version of the managed cluster. Kubernetes 1.16 is available from Rancher 2.3.0 (experimental), generally available in 2.3.2 and the default in 2.3.3.
