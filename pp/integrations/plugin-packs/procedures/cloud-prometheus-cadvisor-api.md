## Pack assets

### Templates

The Monitoring Connector **cAdvisor w/ Prometheus API** brings 4 host templates:

* **Cloud-Prometheus-cAdvisor-Api-custom**: monitors from a single host all the containers matching the filters of each service.
* **Cloud-Prometheus-cAdvisor-Api-Container-custom**: monitors one container running outside Kubernetes (Docker, Podman).
* **Cloud-Prometheus-cAdvisor-Api-Kubernetes-Container-custom**: monitors one container of a Kubernetes pod.
* **Cloud-Prometheus-cAdvisor-Api-Pod-custom**: monitors one Kubernetes pod as a whole.

The last three host templates check that their pod or container is present in the cAdvisor metrics, and are designed to be applied by the [host discovery](#host-discovery).

### Discovery rules

#### Host discovery

| Rule name           | Description                                                                                        |
|:--------------------|:---------------------------------------------------------------------------------------------------|
| Prometheus cAdvisor | Discover pods and containers (Kubernetes or standalone) from cAdvisor metrics stored in Prometheus |

The discovery lists the pods and containers from the `container_last_seen` metric and applies a host template according to the type of each discovered resource:

| Discovered resource                  | Host template                                             | Host name                 |
|:-------------------------------------|:----------------------------------------------------------|:--------------------------|
| Kubernetes pod                       | Cloud-Prometheus-cAdvisor-Api-Pod-custom                  | `namespace_pod`           |
| Container of a Kubernetes pod        | Cloud-Prometheus-cAdvisor-Api-Kubernetes-Container-custom | `namespace_pod_container` |
| Container running outside Kubernetes | Cloud-Prometheus-cAdvisor-Api-Container-custom            | `container`               |

The discovery also fills in the macros of the hosts: the connection to Prometheus, and the **CONTAINER_FILTER**, **POD_FILTER** and **NAMESPACE_FILTER** filters that select the pod or container of each host.

More information about discovering hosts automatically is available on the [dedicated page](/docs/monitoring/discovery/hosts-discovery), in particular about scheduling the discovery job to add the hosts of new pods as your Kubernetes cluster evolves.

## Prerequisites

### Prometheus and cAdvisor

The connector queries the API of a Prometheus server that collects the cAdvisor metrics, from one of the following sources:

* **The cAdvisor built in the kubelet** (Kubernetes): the `/metrics/cadvisor` endpoint of each node, usually collected by the `kubelet` job of the Prometheus Operator. It exports the CPU and memory metrics of the pods and containers, but not the load (`container_cpu_load_average_10s`) and the task state (`container_tasks_state`) metrics, nor the disk usage of the `containerd` containers.
* **A standalone cAdvisor**: on a Docker or Podman host, or deployed in Kubernetes as a DaemonSet. It is required to use the load, storage and task state services.

The default filters use the `container`, `pod` and `namespace` labels set by the kubelet since Kubernetes 1.16 (OpenShift 4.3). On older platforms, these labels are named `container_name` and `pod_name`: set the filters accordingly, for example `--container='container_name!~"|.*POD.*"' --pod='pod_name=~".*"'`.

A standalone cAdvisor deployed in Kubernetes does not set these labels, only the labels of the container runtime (for example `container_label_io_kubernetes_pod_name`): the filters must then use these label names, or Prometheus must be configured to copy these labels to `container`, `pod` and `namespace` (for example with `metric_relabel_configs`).

### Best practice: naming your containers

cAdvisor identifies each container by its name. By default, Docker generates a random name each time a container is recreated,
causing Centreon to create new metrics and a new RRD file in `/var/lib/centreon/metrics` on every change, leading to a proliferation of stale data.

**Always assign a fixed name to each monitored container:**

```bash
# Command line
docker run -d --name my-nginx nginx

# Docker Compose
services:
  web:
    image: nginx
    container_name: my-nginx
```

> If you are using Kubernetes, the pods of a `StatefulSet` keep a stable name (`my-service-0`, `my-service-1`, etc.), as do the pods created directly (`kind: Pod`).
> The pods of the other controllers (`Deployment`, `DaemonSet`, `Job`, `CronJob`, etc.) get a new name each time they are recreated: the host discovery can be configured to add a new host for each name change and to delete the old one, but the metrics collected for two different names will be neither linked nor displayed together.

## How to check in the CLI that the configuration is OK and what are the main options for?

Once the plugin is installed, log into your Centreon poller's CLI using the
**centreon-engine** user account (`su - centreon-engine`). Test that the connector
is able to monitor a resource using a command like this one (replace the sample values by yours):

```bash
/usr/lib/centreon/plugins/centreon_prometheus_cadvisor_api.pl \
	--plugin=cloud::prometheus::exporters::cadvisor::plugin \
	--mode=memory \
	--hostname=10.0.0.1 \
	--url-path='/api/v1' \
	--port='9090' \
	--proto='http' \
	--container='container="nginx"' \
	--pod='pod="web-1"' \
	--extra-filter='namespace="default"' \
	--warning-usage='' \
	--critical-usage='' \
	--warning-working='' \
	--critical-working='' \
	--warning-cache='' \
	--critical-cache='' \
	--warning-rss='' \
	--critical-rss='' \
	--warning-swap='' \
	--critical-swap='' \
	--verbose
```

The expected command output is shown below:

```bash
OK: Container 'nginx' [pod: web-1] Memory Usage: 50.00 MB (50.00% of 100.00 MB), Working: 40.00 MB (40.00% of 100.00 MB), Cache: 10.00 MB, Rss: 38.00 MB, Swap: 0.00 B | 'web-1~nginx#memory.used.bytes'=52428800B;;;0;104857600 'web-1~nginx#memory.working.bytes'=41943040B;;;0;104857600 'web-1~nginx#cache.usage.bytes'=10485760B;;;0; 'web-1~nginx#rss.usage.bytes'=39845888B;;;0; 'web-1~nginx#swap.usage.bytes'=0B;;;0;
Container 'nginx' [pod: web-1] Memory Usage: 50.00 MB (50.00% of 100.00 MB), Working: 40.00 MB (40.00% of 100.00 MB), Cache: 10.00 MB, Rss: 38.00 MB, Swap: 0.00 B
```
