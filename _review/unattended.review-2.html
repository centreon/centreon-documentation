1 · Plain language

The script uses those values to complete the installation on its own, so the process is quick and requires little effort. (l. 10)
Plain language Suggested rewrite: "The script then completes the installation without any further input from you." Why: "the process is quick and requires little effort" is unmeasurable filler — the reader already knows why they chose an unattended install. Saying what the script does (no further input needed) is the actual useful fact.
This is useful when you need to install several central servers with identical settings, when you install from a deployment tool or CI pipeline, or when you have no interactive access to the target machine. (l. 12 — 35 words)
Plain language Suggested rewrite: convert to a bulleted list — "Use an unattended installation when:" followed by three bullets ("you install several central servers with identical settings", "you install from a deployment tool or a CI/CD pipeline", "you have no interactive access to the target machine"). Why: a 35-word sentence with three parallel "when" clauses is a list in disguise. Bullets make the three cases scannable, which is how readers use an intro block.
…when you install from a deployment tool or CI pipeline… (l. 12)
Plain language Suggested rewrite: "from a deployment tool or a CI/CD pipeline". Why: "CI" is an unexpanded abbreviation. It appears nowhere else on the page, so a reader who does not already know it gets no help. "CI/CD pipeline" is the form used across the rest of the documentation and is self-explanatory enough in context.
A full log, including any errors, will be written to /var/log/centreon-unattended-<date>.log. (l. 74)
Plain language Suggested rewrite: "The script writes a full log, including any errors, to /var/log/centreon-unattended-<date>.log." Why: actor-obscuring passive plus future tense. The active present tense names the agent (the script) and matches the tense used in the Options table ("the script installs MariaDB", "the script generates a password").
Installs the central server in TLS mode: the connections to the web interface and to the database are encrypted. Without this option, the central server is installed without TLS. (l. 127)
Plain language Suggested rewrite: "Installs the central server in TLS mode: the script encrypts the connections to the web interface and to the database. Omit this option to install without TLS." Why: two passives in two sentences ("are encrypted", "is installed"). Naming the script as the actor in the first clause and using the imperative "Omit this option" in the second removes both and shortens the cell.

2 · Idiomaticity

The main options are the following: (l. 121)
Idiomaticity Suggested rewrite: "The main options are:" or "Here are the main options:". Why: "are the following" is a literal rendering of « sont les suivantes ». It is grammatical but reads translated; native technical English drops the placeholder noun before a table.
Replace my_username and my_password with the credentials of your RedHat account. (l. 29, l. 47)
Idiomaticity Suggested rewrite: "Replace my_username and my_password with your Red Hat account credentials." Why: "the credentials of your X account" is an of-genitive calque of « les identifiants de votre compte X ». English prefers the attributive form. (See also the Spelling section for "RedHat".)
Level of detail of the log file: DEBUG, INFO, WARN or ERROR. (l. 130)
Idiomaticity Suggested rewrite: "Verbosity level of the log file: …" or "Log level: …". Why: the stacked "Level of detail of the log file" reads awkwardly, and "log level" / "verbosity level" is the established collocation in this domain — it is also what the reader will see in the script's own -h output.
Go to http://<SERVER_IP>/centreon, where <SERVER_IP> is your server's IP address, and log in. (l. 108)
Idiomaticity Suggested rewrite: "Go to http://<SERVER_IP>/centreon (where <SERVER_IP> is your server's IP address) and log in." Why: the comma-delimited relative clause strands "and log in" so far from "Go to" that the sentence has to be re-parsed. Parentheses keep the two imperatives adjacent.
Start using Centreon: follow our Getting started guide to start monitoring your resources. (l. 111)
Idiomaticity Suggested rewrite: "Start using Centreon: follow our Getting started guide to begin monitoring your resources." Why: "Start … start" in one short sentence is an unintentional echo. Swapping the second verb for "begin" (or cutting it: "…guide to monitor your resources") removes it.

3 · Spelling

…with the credentials of your RedHat account. (l. 29 and l. 47)
Spelling Correction: Red Hat (two words, both capitalized) — the vendor's own trademark spelling. Why: "RedHat" is a misspelling of a proper noun. Note for the wider fix: the repository currently contains 12 occurrences of "RedHat" against 1 of "Red Hat", so the error is inherited from the older pages rather than introduced here — worth a repo-wide correction rather than a fix limited to this file.

US/UK spelling: no issues found. The script's center/centre hit is a false positive — the only match is the string centreon inside the download URL (l. 69). No other misspellings or typos found ("autogenerated", "unattended", "MariaDB", "MySQL" are all correct).

4 · Style & terminology

Commands: --tls=enabled (l. 97, 98, 102, 103) — Options table: --tls enabled (l. 127)
Style & terminology Correction: use one form in both places — --tls=enabled, matching the copy-pasteable commands. Why: the same option is documented two ways on one page. This is not only a consistency nit: a reader who copies the syntax from the Options table may run a command the script does not accept. Confirm with the script which separator is valid, then align both.
Commands: -d mysql (l. 92, 93, 102, 103) — Options table: "use -d MySQL to install MySQL instead" (l. 126)
Style & terminology Correction: use lowercase -d mysql in the Options table to match the commands. Why: same problem as above — the value's casing differs between the two tables. Keep the product name capitalized in prose ("to install MySQL instead") but the literal option value lowercase.
"Command with autogenerated admin DB password" / "Command with custom admin DB password" (l. 80–81) vs. "Password of the default admin database account" (l. 128)
Style & terminology Correction: (a) spell out "database" rather than "DB" in the column headers, and (b) verify what -p actually sets. Why: "DB" is an abbreviation used nowhere else on the page — "admin database password" is only a few characters longer in a header that already runs long. More importantly, the 25.10 version of this page documented the same option as "the password for the default admin account", i.e. the Centreon web interface account, not a database account. One of the two pages is wrong about a credential, and the reader cannot tell which. This needs a technical check before publication.
Installation section step numbering: 1. (l. 74) → 4. (l. 108) → 5. (l. 111)
Style & terminology Correction: renumber to 1., 2., 3.. Why: leftover numbering from the reorganization that moved the "update your system" and "download the script" steps into Prerequisites. Docusaurus renumbers ordered lists on render, so the published page looks fine — but the source misleads the next editor, and the 2/3 gap invites the reader of the raw file to think two steps were lost. While renumbering, also align the indentation of the raw <table> block (l. 76–106, 4 spaces) with the 3-space continuation indent used in the Prerequisites steps.
Row "Using MariaDB and no TLS": bash /tmp/unattended.sh install -t central -v 26.10 (l. 87–88)
Style & terminology Correction: add -s, as in the other three rows. Why: this is the only one of the four rows without -s, and -s is defined on the same page as "the script does not prompt you for anything". On a page whose subject is unattended installation, the default MariaDB command is the one that still prompts — almost certainly an omission rather than an intentional difference, and it is the row most readers will copy.
Options table descriptions: "Type of server to install." / "Database to install." / "Password of the default admin database account." / "Silent installation:" / "Level of detail of the log file:" — vs. "Installs the central server in TLS mode:" (l. 125–130)
Style & terminology Correction: recast the --tls description as a noun phrase, e.g. "TLS mode: the script encrypts the connections to the web interface and to the database. Omit this option to install without TLS." Why: five of the six rows open with a noun phrase; only --tls opens with a finite verb. Parallel grammatical form across a reference table lets the reader scan the column instead of reading it.
DEBUG, INFO, WARN or ERROR. (l. 130)
Style & terminology Correction: "DEBUG, INFO, WARN, or ERROR." Why: missing serial (Oxford) comma, which US-English technical style — the register this documentation uses — applies before the final item in a list.
Table column header: "Settings" (l. 79)
Style & terminology Correction: "Configuration" or "Database and TLS options". Why: the column holds four database/TLS combinations, not settings the reader enters. "Settings" also collides with the intro's use of the word for the option values passed to the script (l. 10, l. 12), so one term names two different things on the same page.

Glossary conformity (common.csv + infra-monitoring.csv): no deviations. "central server", "database", "TLS", "web interface" and "Centreon" are used consistently and match the approved source terms. Voice is consistently second person ("you"), and blockquote notes (>) match the convention of the surrounding installation pages — no :::note admonitions are used anywhere in version-26.10/installation/, so the > on l. 14 is correct here.
