1 · Plain language

An unattended installation lets you install a central server by passing all the required settings as options when you run the installation script. The script uses those values to complete the installation on its own, so the process is quick and requires little effort.
Plain language Suggested rewrite: “An unattended installation lets you install a central server by passing all the required settings as options to the installation script. The script then runs the whole procedure, including the web installation, without further input.”
Why: “so the process is quick and requires little effort” is a value claim, not information — the reader cannot act on it. The rewrite replaces it with the fact that actually sells the page, and restores “including the web installation”, which the previous revision stated and this one lost. Also “lets you install … when you run the installation script” repeats “install” three times in one sentence.
Run the script as root. Here is the basic command that installs the central with the default settings :
Plain language Suggested rewrite: “As root, run one of the following commands to install a central server with the default settings:”
Why: “Here is the basic command that…” is a filler frame around the instruction, and “command” is singular while two commands follow. Fold the frame into the imperative. (The stray space before the colon and “the central” are handled under criterion 4.)
In both cases, you will get a full log file with all errors in your tmp folder, named unattended(date).log.
Plain language Suggested rewrite: “Both commands write a full log, including any errors, to /tmp/unattended-<date>.log.”
Why: “a full log file with all errors” reads as if the file contained only errors. Naming the path once, as a path, removes the need for “in your … folder, named …”. (The tmp vs /tmp and the filename pattern are flagged under criterion 4.)
If you don't specify any options when running the script, it will install the central server without TLS, and with MariaDB.
To change this, pass the corresponding options:
Plain language Suggested rewrite: “By default, the script installs the central server with MariaDB and without TLS. To change this, use the following options:”
Why: “If you don't specify any options … it will” is a four-clause way of saying “by default”. Leading with the default also puts the information the reader is scanning for first.
Configure Centreon: log in to the Centreon web interface via the URL http://[SERVER_IP]/centreon where [SERVER_IP] is the real IP address of your server.
Plain language Suggested rewrite: “Configure Centreon: go to http://<SERVER_IP>/centreon, where <SERVER_IP> is your server's IP address, and log in.”
Why: “log in to the web interface via the URL X” makes the URL a subordinate detail when it is the actionable part. Put the address first, the explanation second. (“the real IP address” is flagged under criterion 2.)

2 · Idiomaticity

follow our quick start guide to start your monitoring.
Idiomaticity Suggested rewrite: “follow our quick start guide to start monitoring your resources.”
Why: “start your monitoring” is a calque of « démarrer votre supervision ». In English, monitoring is not a countable thing you own; it takes an object. This phrasing also appears in the 25.10 page, so fixing it here is worth propagating.
where [SERVER_IP] is the real IP address of your server
Idiomaticity Suggested rewrite: “where <SERVER_IP> is your server's IP address”.
Why: “the real IP address” is a literal rendering of « l'adresse IP réelle ». A native reader hears it as “as opposed to a fake one”. The placeholder already implies substitution, so “real” adds nothing; if the contrast must be stated, “actual” is the idiomatic choice.
In both cases, you will get a full log file …
Idiomaticity Suggested rewrite: “Both commands write a full log to …”
Why: “you will get” describes what happens to the reader rather than what the tool does. The repo's house voice for tool behaviour is active and tool-subject (“the script tells you where the password is stored”, used two lines above) — this sentence breaks that pattern.
To get help on the script, use the following command: bash unattended.sh -h
Idiomaticity Suggested rewrite: “To display the script's help, run: bash /tmp/unattended.sh -h”
Why: “get help on X” collocates with people and topics, not with programs; a program's help is displayed. Note also that the path is missing here while every other invocation on the page uses /tmp/unattended.sh — copy-pasted as written, this command fails.

4 · Style & terminology

Here is the basic command that installs the central with the default settings :
Style & terminology Two issues in one line.
(a) Terminology: “the central” → the central server. The glossary entry is Central Server / Serveur central; “the central” is internal shorthand. The page uses the full term correctly in the title, the intro and the Options section, so this is an inconsistency within the page.
(b) Punctuation: remove the space before the colon (“settings :” → “settings:”). This is French typographic spacing left in English text; no other colon on the page is spaced this way.
… in your tmp folder, named unattended(date).log.
Style & terminology Two inconsistencies with the commands directly above.
(a) tmp → /tmp. Every command on the page writes to /tmp/…; bolded tmp without the slash reads as a relative folder.
(b) unattended(date).log does not match what the command produces. The tee pattern generates unattended-MM-DD-YYYY-HHMMSS.log. Write it as unattended-<date>.log and drop the parentheses, which look like literal characters in a filename.
<TabItem value="RHEL 9" label="RHEL 9"> … <TabItem value="Alma / Oracle Linux 9" label="Alma / Oracle Linux 9">
Style & terminology The OS tabs use groupId="os" — correct — but the tab values do not match those used elsewhere in the same group. using-packages.md uses "Alma / RHEL / Oracle Linux 9", "Alma / RHEL / Oracle Linux 10" and "Debian 13". Because Docusaurus syncs tabs by value within a groupId, a reader who picks “Alma / RHEL / Oracle Linux 9” on the packages page lands on this page with an unmatched selection and gets the first tab instead. Align the values with using-packages.md (RHEL is split out here only because of the subscription-manager commands — if the split is intentional, use a distinct groupId rather than the shared os one).
Once you are logged in, follow the steps described here.
Style & terminology Replace the bare “here” with descriptive link text: “follow the initialization of the monitoring steps.” Every other cross-link in this folder names its target (“web installation”, “quick start guide”); “here” is unusable for screen readers and for readers scanning link text.
4. Configure Centreon: log in … / 5. Start using Centreon: follow our quick start guide …
Style & terminology Steps 4 and 5 carry a “Label: instruction” prefix; steps 2 and 3 are plain imperatives. Either give all five steps a label or none. (Step 1, “Update your system:”, is a lead-in to a code block, which is a different pattern and can stay.)
-p <admin_password> … http://[SERVER_IP]/centreon where [SERVER_IP] …
Style & terminology Placeholder syntax is mixed on one page: angle brackets in the commands (<admin_password>) and square brackets in the URL ([SERVER_IP]). Pick one — angle brackets are the more common convention in this folder — and note that square brackets in prose read as Markdown link syntax.

Glossary conformity (common.csv + infra-monitoring.csv): all other terms conform — “central server”, “monitoring”, “web interface”, “database” are used consistently, and product names (Centreon, MariaDB, MySQL, TLS) are capitalized correctly throughout.
