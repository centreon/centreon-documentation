Use a certificate issued by a trusted authority. Self-signed certificates may be used for test purposes, but they MUST NOT be used in production.

* If you already have a certificate validated by an authority, you can proceed to the next step.
* If you do not have a certificate validated by an authority, you can generate one on platforms such as [Let's Encrypt](https://letsencrypt.org/).
* If, for test purposes, you want to use a self-signed certificate, follow [this procedure](../administration/self-signed-certificate.md).

Let's say you have the following files in **/etc/pki/centreon-tls/**:

* rootCA.pem            (public)
* server.pem            (server certificate)
* server-key.pem        (server private key)
{/* * CA/rootCA.\{key,pem\}   (set the following permissions: root:root, mode 0400) */}

1. Install the root CA into the OS trust store of the central server's host machine:

   <Tabs groupId="os">
   <TabItem value="Alma / RHEL / Oracle Linux 9" label="Alma / RHEL / Oracle Linux 9">

   ```shell
   cp /etc/pki/centreon-tls/rootCA.pem /etc/pki/ca-trust/source/anchors/centreon-dev.crt
   update-ca-trust extract
   ```

   </TabItem>
   <TabItem value="Alma / RHEL / Oracle Linux 10" label="Alma / RHEL / Oracle Linux 10">

   ```shell
   cp /etc/pki/centreon-tls/rootCA.pem /etc/pki/ca-trust/source/anchors/centreon-dev.crt
   update-ca-trust extract
   ```

   </TabItem>
   <TabItem value="Debian 13" label="Debian 13">

   ```shell
   cp /etc/pki/centreon-tls/rootCA.pem /usr/local/share/ca-certificates/centreon-dev.crt
   ```

   </TabItem>
   </Tabs>

2. If you are using a remote database, also execute this procedure on the machine that will host the remote database, then copy the root CA certificate of the database machine to the central server host machine's trust store.
