## November 17, 2026

### Centreon Web 26.10.1

<details open>
  <summary>Enhancements</summary>

- [CMA] The freshness threshold rises from 120 to 500 seconds to avoid needless re-checks. Custom values are kept on upgrade.
- [Unattended] Fix path to repo files (RPM).

</details>

<details>
  <summary>Bug fixes</summary>

- Fix(unattended): fixed missing support version 26.10.
- [API] API requests containing invalid non-integer values for the page or limit parameters (e.g., ?page=abc) now correctly return an HTTP 400 Bad Request instead of an uncaught HTTP 500 error, ensuring accurate error reporting and preventing critical log pollution.
- [API] Listing services with the configuration API no longer fails with an error when some of them are deployed by host group.
- [Agent configuration] Deleting a host no longer stops the poller from collecting data from the other hosts using poller-initiated connections.
- [Agent configuration] Errors during automatic host creation are now logged with their real cause instead of a log file permission error.
- [CLAPI] Fixed an issue in the CLAPI export where recurrent downtimes with specific monthly periods (other than "First" or "Last" of the month) were missing.
- [Configuration] Applying a mass change to host templates now correctly removes the services from the old templates instead of only adding the new ones.
- [Configuration] Exporting the configuration no longer hangs at 0% when a resource macro linked to a poller has an empty value.
- [Configuration] Exporting the configuration of pollers with many services is now faster, especially when services use many templates.
- [Configuration] On new installations, the "Never" time period now stops checks as expected.
- [Custom Views] The Host Monitoring widget's CSV export now includes each host's last comment instead of always showing "-".
- [Dashboards] Acknowledgment and downtime modals in resource table widget now use the configured Monitoring defaults.
- [Dashboards] The resource table widget now requires an Open Ticket rule when ticket management is enabled.
- [Downtimes] Multiple recurring downtimes on the same service template via a service group now all apply.
- [Install/update] Fixed a fatal error that caused the upgrade process to abort when encountering non-critical configuration issues (such as an unresolvable central address). The upgrade now correctly logs a warning and continues the process instead of failing.
- [Logs] Filtering by the "Command" type in Administration > Logs now returns command changes, including previously recorded ones.
- [Monitoring] Host group and service group listings no longer time out on large platforms.
- [Performance Graphs] Meta service graphs now display the meta service name as their title, so they are easier to identify on the page.

</details>

<details>
  <summary>Security fixes</summary>

- This release contains security fixes. Details will be available soon on [The Watch](https://thewatch.centreon.com/latest-security-bulletins-64).

</details>

### Centreon Collect 26.10.1

<details>
  <summary>Bug fixes</summary>

- Fixed an issue where Centreon Broker generated irrelevant RRD update error logs when losing connection to pollers, which could saturate the disk partition.
- Fixed an issue where Centreon Engine crashed unexpectedly during configuration application when deleting hosts associated with active service downtimes.
- [Broker] Fixed an issue causing broker to hang on stop with certain database and output configurations.
- [Broker] Fixed remaining false error messages in broker logs that were not fully removed by the previous backport.
- [Engine] Fixed an issue where centengine did not restart automatically after a package update, requiring a manual service restart.
- [Engine] Fixed passive service freshness issues causing engine hangs, memory growth and flapping with CMA checks.
- [Reporting] Fixed an issue where canceled downtimes were wrongly included in availability calculations, causing inconsistent reports.

</details>

## October 20, 2026

### Centreon Web 26.10.0

<details open>
  <summary>Enhancements</summary>

- [Configuration] (Beta) Added a **Create new poller** shortcut in the top banner that generates a single command line for simple poller deployment via container or packages.
- [API] Added an API endpoint for creating pollers.
- [API] Added API endpoints to handle global, installed and standard macros.
- [Administration] The **Administration > About** page has been updated for a new look. Many useful links have also been added to it.
- [Agent configuration] It is now possible to configure both connection directions (poller-initiated or agent-initiated) in the same configuration. The user interface has been updated according to this.
- [Agent configuration] When adding an agent configuration, the **CA common name** field is now displayed only in Insecure TLS mode.
- [Authentication] Added **poller** as a new type of authentication token.
- [Configuration] The BBDO protocol version 3.1.0 is now enabled by default for Broker communications.
- [Configuration] The host categories page has been updated with live search, inline enable/disable and a redesigned add/edit form.
- [Configuration] "Resource macros" are now called "Global macros".
- [Configuration] The **Configuration > Commands > Commands** configuration page has been updated.
- [Top banner] Redesigned the status tiles to make the header clearer and easier to read at a glance.
- [Top banner] The user's profile menu now shows a circular avatar with the user's initials.
- [UI] Resources now use new, consistent icons across the interface for easier identification.
- [UI] Refreshed interface colors: new primary blue, softer table and section headers, and more readable status chips in light and dark modes.

</details>
